# 地图页：右侧控件、地名搜索与手势修复

日期：2026-09-29
状态：待实现

## 1. 为什么做

地图页目前只能看，不能用来干活。

**加点靠误触。** `map.on('click')` 对地图上任何一次轻点都会丢一个黄点并弹出「添加」（`app.js:526`）。平移或双指缩放结束时手指轻轻一抬就会被当成点击，用户的原话是「误触加点」。

**和页面滚动打架。** `.pane` 带 `padding:18px 18px calc(40px + var(--safe-b))`，而 `.map-wrap` 的高度是 `calc(100dvh - 182px - var(--safe-t))`，两者相加比视口高出约 58px，于是地图页整页可滚。`#map` 上也没有任何 `touch-action` 约束，竖向拖动会漏给页面，sticky header 跟着晃。

**顶部太占地方。** 地图上方的 chrome 吃掉 182px：`.hdr`（图标 + 23px 标题 + 副标题 + 三个圆钮）加 `.seg` 标签条。地图自己里面还浮着 `.map-top`（地点数 chip + 三个底图文字按钮）。

**没法远程钉点。** 地名搜索只存在于「添加地点」弹窗里；GPS 也只在那个弹窗里。想在地图上找一个远处的地方钉下来，做不到。

## 2. 现状盘点

大部分能力已经有了，这次主要是搬到地图表面并重新组织交互。

### 已经有的

| 能力 | 位置 | 说明 |
|---|---|---|
| 地名搜索 | `geoSearch()` + `#q` 的 input 处理 | 350ms 防抖、`qSeq` 竞态保护、结果列表渲染，整套可复用 |
| GPS 读取 | 添加弹窗里的 `getCurrentPosition` | 含 denied / fail / insecure 三种错误文案 |
| 底图切换 | `BASEMAPS` + `setBasemap()` + `drawBasemapSwitch()` | 三种底图，状态存 `S.basemap` |
| 地点增删与去重 | `addLocation()` | 含约 11 米内的重复检测 |
| 图钉渲染 | `pinIcon` / `updatePin` / `refreshPins` | 带温度和名称，点击进详情 |

### 需要注意的既有行为

`addLocation()` 末尾是 `hide(); setTab('saved');` —— 每加一个点就跳回「地点」页。弹窗流程里这是对的，地图流程里不是：在地图上连着钉两个点会变成来回跳。

### 缺的

- 地图表面的定位、加点、搜索入口
- 一种不靠点击的放置方式
- 地图页专属的、更矮的顶栏

## 3. 已确认的决策

用户在 brainstorm 中拍板：

1. **只改地图页的顶栏**，地点页一个像素都不动。
2. **加点改成准星 + 拖地图**：按 + 进入放置模式，屏幕正中固定准星，拖地图把目标对进去再确认。普通点击地图不再做任何事。
3. **控件竖排在右侧**（方案 A），不是底部横排。

### 对决策 3 的已知风险与应对

右上角在大屏手机上单手够不到。因此竖排整体垂直居中略微下偏，而不是贴着右上角。底图切换必须从三个文字按钮收成一个图标钮，否则右侧宽度不够。

## 4. 设计

### 4.1 页面结构

```
[顶栏：图标 · 天气地图 · N 个地点 · 语言/说明/设置]   ← 仅地图页压扁，约 120px
[地点 | 地图]                                        ← 变矮
┌──────────────────────────────────┐
│ 🔍 搜索地点                       │  ← 顶部搜索胶囊
│                                  │
│                              ◎   │  ← 定位
│              ✛                   │  ← 准星（仅放置模式）
│                              ＋  │  ← 加点
│                                  │
│                              ▤   │  ← 底图
│ [坐标 · 名称输入 · 确认 / 取消]   │  ← 放置模式时的底部确认条
└──────────────────────────────────┘
```

顶栏压扁靠 `body.map-mode`：`setTab()` 切到地图时加，切走时移除。所有压扁规则都写在 `body.map-mode` 选择器下，地点页不受影响。副标题行在地图页变成「天气地图 · N 个地点」，地点数从地图上的 chip 搬到这里，`.map-top` 那个 chip 撤掉。

### 4.2 页面不再滚动

`body.map-mode #pane-map` 的 padding 归零，高度写死为视口减顶栏；`.map-wrap` 改 `height:100%`。地图页内容高度正好等于可视区，body 没有可滚余量。

`#map` 加 `touch-action:none` 与 `overscroll-behavior:contain`，把手势关在地图里。

### 4.3 右侧竖排

`.map-rail` 绝对定位 `right:12px`，垂直居中略下偏，三个 44px 圆钮自上而下：定位、加点、底图。

底图钮点开后，在竖排左侧弹出现有的三个选项（复用 `drawBasemapSwitch()` 的渲染，换个容器和样式）；再点一次或选中后收起。

### 4.4 搜索

地图顶部一条细胶囊，放大镜图标 + 输入框，左右各留 12px。

取数与竞态完全复用 `#q` 那套：至少 2 个字符才搜、350ms 防抖、`geoSearch()`、自增序号丢弃过期响应。结果列在胶囊下方，每条显示地名、`admin1, country` 与坐标。

点结果 → `map.flyTo([lat, lon], 13)` → **自动进入放置模式**，名称与地区预填为该结果。远程钉一个地方因此是「搜 → 确认」两步，存下来的是真地名而不是坐标串。

### 4.5 放置模式

进入方式：按 +，或点搜索结果。

- 屏幕正中固定准星，`pointer-events:none`，不拦手势
- `.map-foot` 变成确认条：实时经纬度（`moveend` 更新）、名称输入框、确认与取消
- 确认 → `addLocation(o, {stay:true})` → `refreshPins()` → 退出放置模式，**留在地图上**
- 取消 → 退出，不留痕迹

放置状态是一个模块级小对象 `P = {on, name, region}`，不进 `S`，不落盘，切换标签页即失效。

### 4.6 定位

`getCurrentPosition` → `map.flyTo(该位置, 14)`，并在地图上画一个蓝点表示「我在这」。

**只导航，不保存。** 想把当前位置存下来，定位之后按 + 即可——准星此时已经落在自己身上。

### 4.7 对 `addLocation` 的改动

签名改为 `addLocation(o, opts)`：

- `opts.stay === true` 时跳过末尾的 `hide()` 与 `setTab('saved')`
- 返回新建的地点对象，重复时返回 `null`

两个弹窗调用方不传 `opts`，行为逐字不变。

内部那段重复判断抽成纯函数 `findNearby(locations, lat, lon)`，返回命中的地点或 `null`。地图钉点会比弹窗频繁得多地撞到它，而它现在没有任何测试。

### 4.8 手势

1. 删掉 `map.on('click')` 的整段加点逻辑——误触在结构上不再可能，不是靠加判断挡
2. `touch-action` 与高度修正见 §4.2
3. Leaflet 初始化加 `zoomSnap:0`，双指松手后不再吸附到整数缩放级，捏合变连续

**不加缩放按钮。** 用户未提出这一项，右侧也没有多余宽度。

## 5. 数据流

```
切到地图   → body.map-mode + initMap()
定位       → getCurrentPosition → flyTo + 蓝点          （不保存）
按 +       → enterPlace(null)
搜索选中   → flyTo → enterPlace({name, region})
确认       → addLocation(o, {stay:true}) → refreshPins() （留在地图）
取消       → exitPlace()
```

## 6. 错误处理

| 情况 | 行为 |
|---|---|
| 定位被拒 / 读不到 / 非 HTTPS | 复用 `gpsDenied` / `gpsFail` / `gpsInsecure`，走 `toast()`，地图停在原处 |
| 搜索失败 | 复用 `failLoad` / `noNet`，显示在结果列表里 |
| 搜索无结果 | 复用 `noResult` |
| 断网 | 搜索报错；定位照常（GPS 不走网络）；钉点照常存，卡片走现有失败态 |
| 确认时名称为空 | 回退成坐标当名字，与现状一致 |
| 钉在已有点 11 米内 | `dupLoc` toast，退出放置模式，不新建 |
| 放置模式中切走标签页 | 退出放置模式，不保留 |

## 7. 明确不做（YAGNI）

- **缩放按钮**：用户未提，右侧无余量
- **地图上直接编辑或删除已有点**：点图钉进详情页已经能做，不重复造入口
- **搜索历史 / 收藏搜索**：没人要求
- **绘制区域、测距**：与本次目标正交
- **地点页的任何改动**：用户明确只改地图页

## 8. 测试

`findNearby` 是本次唯一的纯逻辑，走 `node --test`：11 米内外的边界、空列表、经度跨 180 度、纬度对距离的影响。

其余是 DOM 与 Leaflet，项目无 DOM 测试框架，沿用实测方式，逐条量化验证：

1. 地图页不可滚动（`scrollHeight === clientHeight`）
2. 点地图任意位置不产生任何标记、不改变 `S.locations`
3. 顶栏在地图页约 120px，切回地点页恢复 182px
4. 定位后地图中心移动到返回的坐标，`S.locations` 长度不变
5. 搜索「Penang」出结果，点第一条后地图中心≈该坐标且进入放置模式，名称预填
6. 放置模式拖地图，确认条坐标跟着变
7. 确认后 `S.locations` +1、地图上多一个图钉、**仍在地图页**
8. 在已有点 11 米内确认 → 不新增，出 `dupLoc` toast
9. 取消后准星和确认条消失，`S.locations` 不变
10. 底图钮展开三个选项，切换后 `S.basemap` 落盘
11. 中/英/马来文下所有新文案正确
12. 断网：搜索报错，其余不白屏

## 9. 风险

**最大的风险是顶栏压扁用错了地方。** 所有规则必须挂在 `body.map-mode` 下；一旦某条漏了这个前缀，地点页会跟着变矮，而用户明确要求地点页不动。实现后必须在两个标签页之间来回切，量出顶栏高度确实在 120 与 182 之间切换。

次要风险：`touch-action:none` 加在 `#map` 上会连带禁掉浏览器对该元素的所有默认手势。Leaflet 自己接管 touch，所以预期没问题，但必须在真机或模拟器上确认双指缩放与单指平移都还正常。
