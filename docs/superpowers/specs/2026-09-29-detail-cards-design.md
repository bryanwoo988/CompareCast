# 详情页：白话摘要、卡片网格与十日概览

日期：2026-09-29
状态：待实现

## 1. 为什么做

用户拿 iOS Weather 作参照，指出它的信息设计更好。对照之下，本应用详情页的问题是：

**满屏数字，没有结论。** 十个数据格子平铺，每个只有一个数值。用户要自己把「降雨概率 86%」「风速 18 km/h」「下午三点」拼成「下午不能喷药」这个判断。iOS 直接给一句话。

**数值没有量感。** 「1007 hPa」不知道是高是低；「风向 SE」不知道指哪；「UV 9」不知道多严重。iOS 用表盘、弧线、色阶条把量感画出来。

**没有整周概览。** 十日列表在上一次改版中被删，换成了顶部日期条。日期条解决了「这是哪一天」，但丢掉了「这一周什么趋势」。

## 2. 不做什么

- **降雨雷达图**：Open-Meteo 不提供雷达瓦片，需另接数据源，属另一个项目
- **月相**：Open-Meteo 不提供
- **气候平均值**：需另一个 API；应用已有的准度核对提供了更有价值的对照
- **体感温度**：用户已明确要求移除，不得借本次改版加回
- **照搬 iOS 的整体外观**：本应用的立身之本是多模式对比与准度核对，那是 iOS 没有的。学它的信息设计，不学它的身份。

## 3. 白话摘要

详情页顶部、日期条下方一行。根据选中日的逐小时数据生成。

判定顺序（先命中先用）：

1. **有成段的雨** → 指出时段与峰值概率：`下午 2 点到 5 点有雨，最高 86%`
2. **零星可能下雨**（有小时超过阈值但不成段）→ `午后可能有零星阵雨，最高 62%`
3. **不下雨但很热** → `全天无雨，最高 34°`
4. **都不显著** → `全天无雨`

时段名称按小时归类：凌晨 0–6、早上 6–12、下午 12–18、晚上 18–24。

「成段」的定义：连续 ≥2 小时概率 ≥ 50%。单独一小时算零星。

摘要只依据选中日的数据，不跨日。选中今天时只描述当前小时之后的时段——已经过去的雨不是行动依据。

## 4. 卡片网格

现有的十格文字表改为两列卡片。每张卡片有标题、主数值，以及一处迷你可视化。

| 卡片 | 可视化 |
|---|---|
| 风 | 罗盘：刻度圈 + 指向风来向的指针，中心是风速 |
| 气压 | 半圆表盘：指针位置按 980–1040 hPa 映射 |
| 日出日落 | 弧线：太阳按当前时刻落在弧上的对应位置 |
| 紫外线 | 渐变色阶条 + 当前值的标记点 |
| 湿度 | 百分比 + 露点一行说明 |
| 能见度 | 公里数 + 一句定性说明 |
| 降雨 | 当日累计 + 概率 |

选中非今天时，无当前时刻概念的卡片（气压、能见度、湿度）不渲染；日出日落弧线改为静态弧线不画太阳。

## 5. 十日概览

加回详情页底部、准度卡片之前。每行：星期 + 日期、天气图标、降雨量、温度区间条、最低/最高温。

与上一版的区别：**可点击**。点某一行即选中该日，页面上方全部内容随之更新，并滚回顶部。日期条与这张表是同一个状态的两个入口。

## 6. 新增字段

`SAFE_CURRENT` 增加 `visibility`、`dew_point_2m`。同一个请求，不增加调用次数。降级用的 `MIN_CURRENT` 不动。

## 7. 纯逻辑

抽到 `summary.js`：

- `rainRuns(probs, minProb, minLen) -> [{from, to, peak}]` — 连续超阈值的时段
- `partOfDay(hour) -> 'night'|'morning'|'afternoon'|'evening'`
- `summarize(stats) -> {kind, ...}` — 返回结构化结论，文案由调用方按语言拼装

结构化而非直接出文案，是为了三种语言共用同一套判定，也为了可测。

## 8. 测试

`summary.js` 走 `node --test`：成段与零星的边界（恰好 2 小时、恰好 50%）、雨在一天两头分成两段、全天无雨、全 null、今天只看当前小时之后。

界面沿用实测：卡片在今天与非今天下的差异、十日列表点击切换日期、三语文案、零地点与断网。

## 9. 风险

**最大的风险是摘要说错话。** 一句「全天无雨」被当成行动依据而实际下了雨，比十个数字摆在那里更糟——数字只是信息，句子是结论。因此阈值必须保守（宁可说「可能有雨」也不说「无雨」），且所有判定走纯函数并有测试覆盖。

次要风险：卡片网格在窄屏上两列会挤。最小宽度 320px 需实测。
