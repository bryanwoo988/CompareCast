# 详情页重构：按日期组织 + 可交互图表

日期：2026-09-28
状态：待实现

## 1. 为什么做

两个真实问题触发了这次重构。

**日期歧义。** 「未来 10 天」那一栏只渲染星期几（`app.js:864`）。10 行标签只有 7 种星期几，所以第 9、10 行和第 2、3 行的文字完全相同（都是「周二」「周三」）。这不是难读，是无法区分。用户的原话是"都不知道到底是哪一个日期，很模糊"。

**看不到某一天的细节。** 10 天列表不可点击，没有绑任何事件。用户想要 iPhone Weather 那种"点进某天 → 看那天每个时刻的天气"，目前完全没有这一层。

用户提供了 iPhone Weather「Conditions」页的三张截图作为参照，明确要求：顶部横向日期条、可触摸的曲线图、手指滑动显示该时刻数值。

## 2. 现状盘点

动手前先弄清楚哪些是新做、哪些是搬运。**大部分是搬运。**

### 已经有的

| 能力 | 位置 | 说明 |
|---|---|---|
| 图表触摸交互 | `buildChart()` `app.js:1040` 起 | pointerdown/move/up 全套，垂直游标线，滑动时实时更新各模式数值 |
| 多模式勾选 | `drawSettings()` 的 `[data-cmp]` | 任意勾选/取消，至少保留一条，存在 `S.compare` |
| 天气状态分类 | `WMO` 表的 `s` 字段 | clear / cloud / rain 三类，已驱动 `.page.rain/.cloud/.night` |
| 请求竞态保护 | `D.seq` / `detailSeq` | 切换地点时旧响应不会覆盖新画面 |

### 数据已经全部在手，不需要新请求

| 函数 | 已取到的数据 |
|---|---|
| `getMain` | 当前模式，`forecast_days=10`，hourly 含 temperature_2m / precipitation / weather_code / wind_speed_10m / is_day |
| `getCompare` | 全部勾选模式，`forecast_days=10`，hourly 含 temperature_2m / precipitation / wind_speed_10m |
| `getExtras` | best_match 的逐小时 precipitation_probability，`forecast_days=10` |

这是本次重构最重要的前提：**没有任何新的网络请求，只是把已有数据按日期切片重新组织。**

### 缺的

- 横向日期条（完全没有）
- 按日期切片的视图（`seriesFor()` 目前固定取"从现在起 48 小时"）
- 曲线渐变填充、H/L 极值标注
- 数值浮在图表上方（现在显示在图表下方的列表里）
- 松手后游标保留（现在松手即消失并跳回起点）
- 模式勾选的就近入口（现在只在设置页深处）

## 3. 已确认的决策

用户在 brainstorm 中拍板：

1. **重构页签**，而不是新开一层。理由：日期条必须放在详情页顶部才能根治"不知道在看哪一天"；保留两套看曲线的入口会更乱。
2. **采用线性布局（方案 A）**，取消页签，整页从上往下一条线读到底。「准度」降级为页面底部的一张普通卡片。
3. **模式线可自由勾选** —— 一条、几条、全部都行，勾选入口要在图表旁边，不是藏在设置里。

### 对决策 2 的已知风险与应对

准度那块统计的是过去一周各模式对 ERA5 的误差，**与用户选中哪一天无关**。把它放进一个按日期组织的滚动流里，用户可能误以为"这是这一天的准度"——那会制造出与本次重构要解决的问题同类的新误解。

设计上必须对冲：准度卡片的标题固定写成「模式准度核对（过去 7 天）」，并在卡片顶部保留现有的 `accWindow` 文案（核对区间 + 样本数），与日期条视觉上明确隔开（整块加一条分隔线和不同的背景层级）。这一点在实现时不可省略。

## 4. 设计

### 4.1 信息架构

详情页从上到下单向滚动，无页签：

```
地点名 / 地区
当前天气图标 + 大温度 + 体感
─────────────────────────
横向日期条（10 天，可滚动，可点）
选中日的完整日期
─────────────────────────
气温曲线（可交互）
模式勾选 chip 排
─────────────────────────
降雨概率曲线（可交互）
─────────────────────────
选中日的逐小时列表
─────────────────────────
选中日的详细数据格子（体感/湿度/风/气压/日出日落…）
─────────────────────────
模式准度核对（过去 7 天）← 与日期无关，视觉上隔开
─────────────────────────
重命名 / 删除地点
```

顶部的 `.d-bar`（返回键 + 模式按钮）保持现有的 sticky 行为。日期条同样 sticky，贴在 `.d-bar` 下方——滚到页面任何位置都能换一天，这是线性布局能成立的前提。

### 4.2 日期条

```
 日   一   二   三   四   五   六
 28  29   30    1    2    3    4
 ●
```

- 数据源：`D.main.daily.time`（10 天）
- 每格两行：星期几缩写（`toLocaleDateString(locale(), {weekday:'narrow'})`）+ 日期数字
- 今天：数字用主题蓝色
- 选中日：白色实心圆底 + 深色数字
- 横向滚动，选中项自动 `scrollIntoView({inline:'center'})`
- 下方一行完整日期：`2026年10月3日 星期六`（按 `locale()` 本地化）

选中状态存在 `D.day`（0–9 的索引），默认 0。切换地点时重置为 0。

### 4.3 按日切片

新增一个纯函数，替代 `seriesFor()` 中写死的"从现在起 48 小时"：

```
sliceDay(src, dayIndex) -> {start, n, times}
```

从 `D.main.daily.time[dayIndex]` 取出日期字符串（`YYYY-MM-DD`），在 hourly 的 `time` 数组里找到该日期的首末索引。当天通常是 24 个点。

边界情况：
- **今天**：仍然返回完整 24 小时（0 时起），而不是从当前小时起。iPhone Weather 就是这样，用户能看到今天已经过去的时段。当前时刻在图上用一条淡色竖线标出。
- **最后一天**：某些模式在第 10 天可能不足 24 小时，按实际长度渲染，不补空。
- **找不到该日期**：返回空，图表区显示 `—`，不抛错。

### 4.4 图表

在现有 `buildChart()` 基础上改造，不重写。

**新增的视觉：**
- 曲线下渐变填充：从线色 `opacity .38` 渐变到 `0`，只对**单条线**启用；勾选多条时关闭填充（七层半透明叠加会糊成一片）
- H / L 标注：单条线时，在最高点和最低点画小圆点 + 文字标签
- 当前时刻竖线：仅在选中"今天"时显示

**交互改动：**
- 数值标签从图表下方移到**图表正上方**，格式 `14:00  ☁ 29°`，跟随游标
- 松手后游标**保留在原地**，不再消失、不再跳回起点（改 `release()`）
- 多条线时，浮动标签显示当前模式的值，其余模式的值仍在下方列表实时更新

**保留不动的：** pointer 事件绑定、坐标换算、网格线、轴标签。这部分现有实现是正确的。

### 4.5 模式勾选

图表下方一排横向滚动的 chip：

```
[✓ ECMWF] [✓ GFS] [  ICON  ] [  GEM  ] …
```

- 直接读写 `S.compare`，与设置页共用同一份状态
- 点击即时切换，立刻重画图表，不需要重新请求（`D.cmp` 已有全部模式数据）
- 至少保留一条：只剩一条时点它不生效（沿用 `drawSettings()` 现有规则）
- 每个 chip 带模式色圆点，勾选态白底深字，未选态半透明

设置页里那一组勾选**保留不动**，两处读写同一个 `S.compare`，改任一处另一处下次打开时反映最新状态。

### 4.6 降雨概率图

独立一张图，同样可交互。数据来自 `D.ext.hourly.precipitation_probability`（best_match），按选中日切片。

沿用现有的 `probSrc` 文案说明"降雨概率来自 Best Match 混合模式"——这个来源标注不能丢。

`D.ext` 取不到时（`'fail'`），整块不渲染，不显示空图。

### 4.7 逐小时列表与数据格子

- 逐小时横向列表：改为显示**选中日**的 24 小时，而不是"从现在起 24 小时"。标题相应从「未来 24 小时」改为该日日期；选中今天时当前小时那一格标为「现在」，选其他日期时不标
- 数据格子（体感/湿度/风/气压/UV/日出日落）：选中今天时显示 `current` 的实况值；选中其他日期时显示该日的 daily 聚合值（最高/最低/降雨总量/日出日落），并把小标题从「当前实况」改为该日日期

这一条是必要的：选中 10 月 3 日却显示今天的实时气压，是新的误导。

## 5. 数据流

```
openDetail(id)
  └ D.day = 0
  └ loadDetail()
       ├ getMain      → D.main  （当前模式 10 天 hourly + daily）
       ├ getExtras    → D.ext   （逐小时降雨概率）
       └ getCompare   → D.cmp   （多模式 10 天 hourly）

点日期条 → D.day = i → paintDetail()   （纯重绘，无请求）
点模式 chip → 改 S.compare → buildChart()  （纯重绘，无请求）
```

切换日期和切换模式都是**纯前端重绘**。这是本设计的核心性质，必须在实现中保持——一旦某个交互触发了网络请求，说明切片逻辑写错了。

## 6. 错误处理

| 情况 | 行为 |
|---|---|
| `D.main` 未到 | 整页显示 loading，日期条不渲染 |
| `D.cmp` 为 `'fail'` | 图表只画当前模式单线，chip 排显示但置灰不可点 |
| `D.ext` 为 `'fail'` | 降雨概率整块不渲染；逐小时列表不显示百分比 |
| 某模式在选中日全为 null | 该模式不进 series，chip 上加一个"无数据"点 |
| 选中日超出 hourly 范围 | 图表区显示 `—`，其余部分正常 |

沿用现有的 `D.seq` 竞态保护。日期切换不产生请求，因此不涉及新的竞态。

## 7. 明确不做（YAGNI）

- **Actual / Feels Like 切换**：截图里有，但体感温度已经在数据格子里了，为它单开一个图表层级不值得。等用户明确要求再说。
- **Daily Summary 文字描述**："周六最低 24° 出现在早上 6-7 点"这类句子，需要一套多语言模板生成器，收益低于成本。
- **天气背景动画**：上一轮讨论过但未定案，与本次重构正交，单独处理。
- **地点列表页改成全屏滑动卡片**：属于导航层重写，本次不碰。

## 8. 测试

没有测试框架，沿用实测方式：

1. **日期歧义已消除**：日期条每一格显示的日期数字唯一，完整日期行与所选格一致
2. **切日期零请求**：打开 DevTools Network，连点 10 个日期，网络面板无新请求
3. **切模式零请求**：同上，连点所有 chip
4. **今天的特殊处理**：选中今天时，图上有当前时刻竖线；数据格子显示实况值
5. **选非今天**：数据格子标题变为该日日期，显示的是该日聚合值而非实况
6. **游标保留**：手指松开后游标停在原地
7. **降级路径**：断网后重进详情页，各块按第 6 节的表格降级，不白屏
8. **三种语言**：中/英/马来文下日期格式、星期缩写正确
9. **准度卡片**：标题含"过去 7 天"，与日期条视觉隔开

## 9. 风险

**最大的风险是 `paintForecast()` 会膨胀。** 它现在已经近 100 行，要再塞进日期条、两张图、chip 排、按日切片的格子，会变成一个没人能读的函数。

实现时必须拆开，每个渲染块一个函数，各自只负责一段 HTML 和自己的事件绑定：

```
paintDetail()        总装
  ├ renderDayStrip()   日期条
  ├ renderTempChart()  气温图 + chip 排
  ├ renderProbChart()  降雨概率图
  ├ renderHourStrip()  逐小时
  ├ renderCells()      数据格子
  └ renderAccuracy()   准度卡片（复用现有 paintAccuracy 的渲染部分）
```

`buildChart()` 同样要把"画图"和"绑交互"分开，两张图共用同一套交互代码，不复制粘贴。

次要风险：日期条 sticky 叠在已经 sticky 的 `.d-bar` 下面，两层 sticky 的 `top` 值要手算对齐，在有 `safe-area-inset` 的 iPhone 上尤其容易错位。实现后必须在真机或模拟器上验证。
